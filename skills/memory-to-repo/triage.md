# Разбор памяти одного проекта (промпт сабагенту)

Подставь вместо `<…>` запись проекта из `memtool.py inventory`, путь к глобальному `~/.claude/CLAUDE.md` и отдай текст ниже сабагенту.

---

Ты разбираешь локальную память Claude Code одного проекта. Решать будет человек, ты готовишь ему таблицу. Ничего не правь и не удаляй: только читай.

Проект: `<path>` (git: `<repo.root или «не репозиторий»>`, основная ветка `<repo.default>`).
Память: `<memory_dir>` — прочитай `MEMORY.md` и **каждую** запись целиком.
Инструкции проекта: `<repo.instructions>` и документы, на которые они ссылаются. Глобальные инструкции человека: `<~/.claude/CLAUDE.md>`.

Для каждой записи найди, есть ли её смысл в инструкциях или документах репозитория: ищи по ключевым словам (`grep -ril … | head`), а не читай весь репозиторий. Потом отнеси запись к одной категории:

- **есть** — смысл уже записан в репозитории или в глобальном `CLAUDE.md`. Улика: `путь:строка`.
- **в репо** — правило или знание, нужное любому, кто работает с проектом (команды, договорённости, грабли, термины), а в репозитории его нет. Дай цель (файл и раздел) и готовый текст вставки: язык и стиль целевого файла, 1–3 строки, без дат и истории «как к этому пришли».
- **мне** — про самого человека в любом проекте: язык, как общаться, привычки (например, диктует голосом). Готовый текст для глобального `CLAUDE.md`, если там такого ещё нет.
- **локально** — личное, но только про этот проект: доступы человека, пути на его машине, его роль в команде. Готовый текст для `CLAUDE.local.md`.
- **устарело** — состояние или история: «остановились…», планы, статусы задач, решения, которые уже в коде или в трекере; или запись противоречит репозиторию (улика).
- **спорно** — не можешь решить. Сформулируй вопрос человеку с твоей рекомендацией.

Если две записи говорят одно и то же — отметь это, вставка нужна одна. Незакоммиченные изменения в проекте не мешают: вставки пойдут отдельной веткой от основной.

Вопросы человеку — только в разделе «спорно».

Ответ — только таблица и вопросы, без пересказа записей:

```
<path> — <N> записей
есть (k): file1.md → CLAUDE.md:12; file2.md → docs/X.md:40; …
устарело (k): file3.md — статус задачи #12, закрыта; …
в репо (k):
  file4.md → AGENTS.md, «Тесты»: «<текст вставки>»
мне (k):
  file5.md: «<текст>»
локально (k):
  file6.md: «<текст>»
спорно (k):
  file7.md — <вопрос>? Рекомендую: <категория и почему>
```

Готово, когда каждая запись из папки памяти стоит ровно в одной строке таблицы.
