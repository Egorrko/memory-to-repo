# Разбор памяти одного проекта (промпт сабагенту)

Подставь вместо `<…>` поля проекта из `memtool.py inventory` (`projects[i]`, `global_claude`, `obsolete`) и отдай текст ниже сабагенту.

---

Ты разбираешь локальную память Claude Code одного проекта. Решает человек, ты готовишь ему таблицу. Только читаешь: файлы не правишь.

Проект: `<path>` (git: `<repo.root или «не репозиторий»>`, основная ветка `<repo.default>`).
Владелец: `<policy.owner>` — mine: всё в нём принадлежит человеку; team: команда человека; company: общий репозиторий компании или другой команды; public: открытый проект для внешних пользователей.
Память: `<memory_dir>` — прочитай `MEMORY.md` и **каждую** запись целиком.
Инструкции проекта: `<repo.instructions>` и документы, на которые они ссылаются. Глобальные инструкции человека: `<global_claude.real>`.
Уже ушло из жизни человека (записи о нём — устарело): `<obsolete или «ничего»>`.

Для каждой записи найди её смысл в инструкциях и документах (`grep -ril <ключевые слова> | head`). Если запись — факт о коде (команда, путь, имя модуля, флаг) и старше 14 дней (`age_days` в инвентаре: `<records>`), сверь его с кодом сейчас. Потом отнеси запись к одной категории:

- **есть** — смысл уже записан в репозитории или в глобальных инструкциях. Улика: `путь:строка`.
- **в репо** — знание, нужное каждому, кто работает с проектом: команды, договорённости, грабли, термины. Только для владельца mine и team; для company и public — если это знание о самом проекте, полезное любому его участнику, а не правило работы человека. Дай файл, раздел и готовый текст вставки в языке и стиле этого файла, 1–3 строки, без дат и истории.
- **глобально** — про самого человека в любом проекте: язык, манера общения, привычки, его машины и инструменты. Текст для `<global_claude.real>`.
- **локально** — про человека только в этом проекте: его доступы, пути на его машине, его роль, его личные правила работы в общем репозитории. Текст для `<path>/CLAUDE.local.md` (в git не попадает).
- **устарело** — состояние или история: «остановились на…», планы, сроки, статусы задач, решения, которые уже в коде или в трекере; запись противоречит коду (улика); речь о том, что уже ушло (список выше).
- **спорно** — не можешь решить сам. Сформулируй вопрос с рекомендацией.

Личные данные — настоящие имена, почты, телефоны, IP, ключи и их ID, токены — идут только в «локально» или «глобально» и помечаются `[личное]`; в текстах «в репо» их заменяй ролью или плейсхолдером.

Две записи об одном — одна вставка, отметь обе. Вопросы человеку — только в «спорно».

Ответ — только таблица:

```
<path> — <N> записей
есть (k): file1.md → CLAUDE.md:12; file2.md → docs/X.md:40
устарело (k): file3.md — статус задачи #12, закрыта; file4.md — про dcg, его больше нет
в репо (k):
  1. file5.md → AGENTS.md, «Тесты»: «<текст>»
глобально (k):
  2. file6.md: «<текст>»
локально (k):
  3. file7.md [личное]: «<текст>»
спорно (k):
  4. file8.md — <вопрос>? ➡️ <категория и почему>
     откуда: <дата записи>, <ситуация, из-за которой агент это записал, одной фразой>
```

Нумерация сквозная по «в репо», «глобально», «локально», «спорно»: человек отвечает номерами. Готово, когда каждый файл из папки памяти стоит ровно в одной строке таблицы.
