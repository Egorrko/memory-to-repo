# Память → репозиторий

Локальная память Claude Code (`~/.claude/projects/*/memory/`) у каждого своя: агент одного человека работает по правилам, которых нет у коллег, а когда правило в репозитории меняется, копия в памяти остаётся старой. Этот скилл проходит с человеком по всем проектам и раскладывает каждую запись туда, где её видят все, кому она нужна. В конце память выключается.

Скрипт `memtool.py` лежит рядом с этим файлом; запускай его `python3 <папка скилла>/memtool.py …`. Прогресс он хранит в `~/.claude/memory-archive/progress.json`, так что разбор можно прервать и продолжить в новой сессии тем же скиллом. Разобранная память не удаляется, а переезжает в `~/.claude/memory-archive/`.

Запускать из домашней папки (`cd ~ && claude`), чтобы были доступны все проекты.

## 1. Начало

`memtool.py status`. Если разбор уже идёт — скажи, сколько пройдено, и продолжай с шага 2 со следующего проекта.

Иначе `memtool.py inventory` и коротко покажи человеку:

- сколько записей и в скольких проектах; топ-3 проекта по числу записей;
- сколько весят оглавления: `index_bytes / 4` ≈ токенов, которые подгружаются в начало **каждой** сессии в этих проектах;
- план: N шагов (по одному на проект с живой папкой, один общий на проекты, которых больше нет, финальный), обычно 1–3 вопроса на шаг. Чем закончится: ветки `memory-to-repo` с коммитами в репозиториях (пушит сам человек), правки в его `CLAUDE.md`, память выключена.

Спроси «Начинаем?» и жди ответа.

## 2. Проект за проектом

Каждое сообщение шага начинай с `**Шаг k/N** · <путь> · <записей>`.

**Разбор.** Отдай проект сабагенту с промптом из [`triage.md`](triage.md) — сам записи и репозиторий не читай, так твой контекст выдержит все проекты. Пока человек отвечает по текущему проекту, запускай в фоне разбор следующего.

**Вопрос.** Покажи таблицу сабагента и спроси одним вопросом (AskUserQuestion):

- «Принять всё как предложено» (рекомендуемый);
- «Пройтись по спорным» — тогда пункты `в репо`, `мне`, `локально` и `спорно` нумерованным списком в формате grilling: вопрос, ➡️ рекомендация, «да» принимает рекомендацию; человек называет только исключения;
- «Пропустить проект» — память проекта не трогаешь, он остаётся на следующий запуск.

**Применение** — только принятое:

- `в репо` — отдельная рабочая копия, чтобы не трогать незакоммиченное человека:
  `git -C <root> worktree add <tmp> -b memory-to-repo <default>` (ветка уже есть — без `-b`, на неё). Вставь тексты, `git commit -m "Знания агента из локальной памяти → инструкции репозитория"`, `git worktree remove <tmp>`. Не пушь.
- `локально` — `CLAUDE.local.md` в корне проекта. Проверь `git check-ignore -q CLAUDE.local.md`; не игнорируется — допиши его в `.git/info/exclude`, не в `.gitignore`.
- `мне` — в `~/.claude/CLAUDE.md`, без повторов того, что там уже есть.
- `есть`, `устарело` — ничего.
- Папка не репозиторий (например, `~` или общая папка проектов): `в репо` здесь нет — такие записи предлагай как `мне` или `локально` (`CLAUDE.local.md` в этой папке).

Затем `memtool.py done <id>` — он переносит память проекта в архив и печатает, сколько осталось.

Шаг закончен, когда каждая запись проекта применена, отклонена человеком или проект пропущен, и `done` выполнен.

**Проекты, которых больше нет** (`exists: false`) — один общий шаг: таблица по всем, рекомендация «мне» для записей о человеке, остальное — «устарело». Потом `done` для каждого.

## 3. Финал

`**Шаг N/N** · итог`. Покажи:

- ветки `memory-to-repo` по репозиториям с числом коммитов — их человек смотрит и пушит/открывает PR сам;
- что добавлено в `~/.claude/CLAUDE.md` и в `CLAUDE.local.md`;
- пропущенные проекты.

Допиши в `~/.claude/CLAUDE.md` правило:

```
## Память
Автопамять Claude Code выключена. Знание о проекте предлагай правкой CLAUDE.md / AGENTS.md / docs репозитория (покажи diff), знание обо мне — правкой этого файла.
```

Если проекты пропущены — спроси, выключать ли память сейчас (рекомендуй: да, их записи останутся в папках и разберутся следующим запуском). Затем `memtool.py finish` и скажи человеку перезапустить открытые сессии Claude Code.
