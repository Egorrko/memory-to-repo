# Память → репозиторий

Локальная память Claude Code (`~/.claude/projects/*/memory/`) у каждого своя: агент одного человека работает по правилам, которых нет у коллег, а когда правило в репозитории меняется, копия в памяти остаётся старой. Этот скилл проходит с человеком по всем проектам, раскладывает каждую запись туда, где её видят все, кому она нужна, публикует изменения и выключает память.

Скрипты лежат рядом с этим файлом, запуск — `python3 <папка скилла>/<скрипт>`. `memtool.py` хранит прогресс и ответы человека в `~/.claude/memory-archive/progress.json`: разбор можно прервать и продолжить тем же скиллом в новой сессии. Разобранная память переезжает в `~/.claude/memory-archive/`.

**Куда что идёт** — эту легенду покажи человеку один раз в начале, дальше используй те же слова:

| Категория | Куда |
|---|---|
| в репо | файл инструкций или docs репозитория проекта |
| глобально | глобальный `~/.claude/CLAUDE.md` — про человека во всех проектах |
| локально | `<проект>/CLAUDE.local.md` — про человека в этом проекте, в git не попадает |
| есть, устарело | никуда, только в архив |

**Вопросы — обычным текстом в чате.** Нумерованный список, у каждого пункта ➡️ рекомендация; человек отвечает «да» (принять все рекомендации) или номерами исключений. Так таблица и вопросы всегда видны вместе.

## 1. Начало

`memtool.py status`. Разбор уже идёт — скажи, сколько пройдено, и продолжай с шага 2.

Иначе `memtool.py inventory` и коротко покажи человеку: сколько записей в скольких проектах, топ-3 проекта, сколько токенов уходит на оглавления (`index_bytes / 4` в начало **каждой** сессии в проекте). Предложи `memview.py`: страница со всем, что агент о нём помнит; отметки с неё, скопированные в чат, — его готовые решения.

Затем три вопроса одним сообщением, с рекомендациями:

1. **Чьи это проекты.** Сгруппируй проекты по полю `root` и для каждого корня спроси владельца и публикацию:
   - владелец: `mine` — всё его; `team` — его команда; `company` — общий репозиторий компании или чужой команды (туда только знание о самом проекте, правила человека — в `CLAUDE.local.md`); `public` — открытый проект для внешних людей;
   - публикация: `direct` — пуш в целевую ветку; `pr` — ветка и PR; `none` — коммит остаётся у человека.
   Отдельные проекты внутри корня с другим владельцем человек называет сам.
2. **Что ушло.** Какими инструментами, сервисами, правилами он больше не пользуется — записи о них станут «устарело».
3. **Начинаем?**

Ответы запиши: `memtool.py policy <root> <owner> <publish>` на каждый корень и проект-исключение, `memtool.py obsolete "<текст>"` на каждый пункт.

**Разбор всех проектов сразу.** Запусти сабагентов с промптом из [`triage.md`](triage.md) в фоне, по 3–4 параллельно, на все проекты с `exists: true`. Сам записи и репозитории не читай: так твой контекст выдержит весь разбор. Пока сабагенты работают, человек отвечает на первые шаги.

План (сколько шагов) покажи, когда готовы первые таблицы: проект на шаг; проекты одного корня по ≤3 записи — один шаг на всех; проекты, которых больше нет (`exists: false`), — один шаг; финал.

## 2. Шаги

Сообщение шага начинай с `**Шаг k/N** · <путь> · <записей>`. Строки «есть» и «устарело» покажи одной строкой каждую, без вопросов. Остальное — таблица сабагента с номерами и вопрос: «да / номера исключений / пропустить проект».

**Применение** — только принятого:

- `в репо` — коммит в отдельной рабочей копии по [`git.md`](git.md): целевая ветка, хуки, публикация. Владелец `company` или `public` — перечитай текст: в нём знание о проекте, без правил и данных человека.
- `глобально` — в `global_claude.real`. Это симлинк в репозиторий (`global_claude.repo` есть) — закоммить там только свой кусок, как в разделе «Правка файла, который у человека уже изменён» в `git.md`, и запиши `memtool.py branch <repo> <его ветка> <его ветка>`.
- `локально` — `CLAUDE.local.md` в корне проекта; проверь, что git его игнорирует (`git.md`, «CLAUDE.local.md»).
- Папка проекта не репозиторий (например, `~`): «в репо» там нет, такие записи идут в «глобально» или «локально».

Затем `memtool.py done <id>`: память проекта уходит в архив.

Шаг готов, когда каждая запись применена, отклонена человеком или проект пропущен, и `done` выполнен.

**Проекты, которых больше нет** — один шаг на все: записи о человеке — «глобально», остальное — «устарело». Потом `done` для каждого.

## 3. Финал

`**Шаг N/N** · итог`.

1. Допиши в глобальный `CLAUDE.md`:
   ```
   ## Память
   Автопамять Claude Code выключена. Знание о проекте предлагай правкой CLAUDE.md / AGENTS.md / docs репозитория (покажи diff), знание обо мне — правкой этого файла.
   ```
2. Покажи списком, что опубликуется: `memtool.py status`, строки «Ветка …» — репозиторий, ветка, куда (`direct` / PR в `<target>`). Плюс что добавлено в глобальный `CLAUDE.md` и в `CLAUDE.local.md`, и пропущенные проекты. Спроси одно: «Публикую?».
3. Опубликуй по разделу «Публикация» в `git.md`. Покажи ссылки на PR.
4. Пропущенные проекты есть — спроси, выключать ли память сейчас (➡️ да: их записи останутся на месте и разберутся следующим запуском). `memtool.py finish`.
5. `memtool.py cost` — покажи минуты и доллары. Скажи перезапустить открытые сессии Claude Code.

Разбор готов, когда `memtool.py status` показывает «память выключена», а каждая ветка опубликована или оставлена по решению человека.
